# 账号平台迁移

合并版本保留现有账号、Cookie 文件、素材与发布历史。两个旧分支曾把数字类型 `12`–`16` 分配给不同平台，因此升级时不能仅凭数字自动认定账号归属。未保存明确平台绑定的这些旧账号会显示「平台待确认」，确认前暂停编辑和发布使用；即使来自 main，也需要确认一次。新建账号会同时保存数字类型与平台标识。

## 类型映射

| 旧类型 | main 分支平台与当前类型 | work 分支平台与当前类型 |
| --- | --- | --- |
| 12 | 一点号 `yidian` → 12 | 微信公众号 `wechat` → 25 |
| 13 | 大鱼号 `dayu` → 13 | 京东图文 `jd` → 26 |
| 14 | 网易号 `netease` → 14 | 小红书商家号 `xiaohongshu_merchant` → 27 |
| 15 | AcFun `acfun` → 15 | 懂车号 `dongchedi` → 24 |
| 16 | 快传号 `kuaichuan` → 16 | 淘宝光合 `taobao` → 28 |

main 的京东长文章 `jingdong` 始终使用类型 18，原生内容为 `style=0`；work 的京东 `jd` 为图片笔记 `style=25`，现在使用类型 26。两者不能互换。视频号 `tencent` 仍为类型 2，企鹅号 `qiehao` 仍为 11，微信公众号为 25。

## 在网页确认旧账号

升级前停止后台任务，备份数据库、`cookiesFile/` 和 `articleData/`。随后启动新版服务，按以下步骤处理：

1. 打开「账号管理」的「全部」页，找到显示「平台待确认」或「待确认（旧编号 n）」的账号。
2. 点击「确认所属平台」。窗口仅提供该旧编号对应的两个候选平台；根据原账号的实际用途选择。
3. 点击「确认并保留原账号」。系统先生成数据库备份，再在同一事务中更新类型并保存稳定平台绑定。
4. 确认后检查账号状态，必要时刷新登录状态，再运行目标平台预览。确认平台只确定账号归属，不证明会话有效或已有发文权限。

若会话文件名包含已知平台标识，窗口仅提示可能的平台，不会预选或自动迁移。无法确定归属时保留待确认状态，先核查原使用记录；不要删除旧账号或修改 Cookie 来绕过确认。普通账号编辑只能改名，不能切换平台。

确认保留原账号 ID、名称、状态、会话路径、Cookie 文件和发布历史，只更新 `user_info.type` 并新增 `account_platform_bindings` 记录。已有文章任务快照与历史记录不会被重新解释为另一个平台；后续执行仍须匹配明确的账号平台。旧 work 懂车号迁入类型 24 后，新的发布目标须满足当前双封面与 H1 正文限制，详见[文章说明](./articles.md)。

每次首次确认前，SQLite 一致性备份写入数据库同目录的 `account-migration-backups/*.db`。备份包含私密账号和内容数据，应与数据库同等保护，不提交到仓库。此备份不包含 Cookie 和素材文件，完整恢复仍需前述目录备份。需要恢复时先停止服务并保留当前数据，再由维护者核对后恢复一致的数据集；不要在运行中替换数据库。

## API

账号列表继续保留原有五列 `data` 格式，同时返回顶层 `accountIdentities`。每个身份对象包含 `platform`、`needs_confirmation`、`reason`、`candidates` 与 `suggested_platform`；建议平台只是提示，不能代替明确选择。

确认接口为 `POST /confirmAccountPlatform`，JSON 示例：

```json
{"id": 42, "platform": "wechat", "expectedType": 12}
```

`id` 为原账号 ID；`expectedType` 是当前页面读到的旧编号，用于拒绝并发变化；`platform` 必须是该编号的候选标识。示例表示用户已确认原类型 12 实际属于公众号，不可直接套用到其他账号。成功响应包含 `account_id`、`platform`、当前 `type`、`already_confirmed` 和首次迁移的 `backup_path`。相同绑定重复确认不重复迁移；账号已变化或平台不匹配时返回 409，须刷新后核对，不盲目重试。

确认不会调用平台登录、上传或发布接口。文章 API、视频入口和后台账号检查均继续核对平台绑定，待确认账号不能靠旧数字类型进入其他平台流程。
